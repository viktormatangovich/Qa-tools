# QA Tools

> Текущая версия Reqpane: **2.2.1**

**Reqpane** — это расширение для Chrome, которое перехватывает и отображает все API-запросы, ошибки консоли и сетевую активность прямо в боковой панели браузера. Создано для QA-инженеров и разработчиков, чтобы упростить отладку, тестирование и анализ сетевого взаимодействия веб-приложений.

---

## Возможности

### 📡 Перехват запросов

- Перехватывает все вызовы `fetch` и `XMLHttpRequest`
- Захватывает заголовки и тела запросов/ответов
- Отслеживает длительность запросов и коды статусов
- Перехват консольных ошибок (errors, unhandled rejections, console.error)
- Автовыбор — автоматический фокус на новых запросах

### 🔍 Фильтрация и поиск

- Фильтры: Все, Ошибки (4xx/5xx), Медленные (>1с), Ошибки консоли
- Фильтрация по шаблону URL
- Поиск по содержимому тела запроса и ответа

### 👁️ Режимы просмотра

- **Список** — хронологический список запросов
- **Таймлайн** — визуальная шкала времени с длительностями
- **Группировка** — группировка по доменам

### 🔄 Сравнение запросов

- Выберите два запроса для сравнения бок о бок
- Визуальный diff заголовков, тел и метаданных

### 🎭 Моки (Mock Responses)

- Создавайте правила моков с шаблонами URL и HTTP-методами
- Возвращайте произвольные коды статусов и тела ответов
- Включайте/отключайте правила на лету
- Кроме подмены ответа правило может изменить отдельные поля настоящего ответа, задержать или заблокировать запрос

### 🛑 Точки остановки (Breakpoints)

- Приостанавливайте запросы перед отправкой или при получении ответа
- Меняйте URL, метод, заголовки и тело запроса либо статус, заголовки и тело ответа; продолжайте или отменяйте запрос
- Сопоставление URL по шаблону

### ⚡ Нагрузочное тестирование

- Воспроизводите любой захваченный запрос многократно (1–100 итераций)
- Настраиваемая конкурентность (1–10 параллельных запросов)
- Регулируемая задержка между пакетами и таймауты
- Прогресс в реальном времени с отслеживанием успехов/ошибок
- Детальная статистика: avg/min/max/median/p95/p99 время ответа
- Гистограмма распределения задержек
- Пропускная способность (запросов в секунду)
- Группировка и анализ ошибок
- Сохранение и просмотр истории тестов

### ✅ QA Check и контрактные проверки

- **Автоматический QA-анализ** — находит HTTP 4xx/5xx, неуспешные и медленные запросы, повторяющиеся вызовы и ошибки консоли
- **Проверка доступности** — по запросу сканирует страницу на загруженные битые изображения, отсутствующий `alt`, элементы формы и кнопки без доступного имени
- **Проверка OpenAPI 3.x** — импортируйте JSON-спецификацию из файла или URL, чтобы сверять маршруты, статусы и поддерживаемую часть схем ответов; отображается покрытие API-контракта
- **Граничное и негативное тестирование API** — на вкладке «Негатив» формирует варианты `null`, пустого значения, неверного типа, отсутствующего поля и граничных значений; при импортированном OpenAPI учитывает `minimum`, `maximum`, `minLength` и `maxLength`. Вариант открывается в «Правке», а отправку запроса QA выполняет вручную.
- **Негативные ответы без внешних вызовов** — создаёт для выбранного URL локальные моки `401`, `403`, `404`, `409`, `429`, `500`, `503`, задержек и тайм-аута
- **Отчёты и сравнение окружений** — создавайте баг-репорты и экспортируйте отчёт сессии в Markdown, HTML или JSON; сравнивайте две сохранённые сессии без отправки запросов во внешние среды

Все QA-проверки и их доказательства обрабатываются локально в браузере. Тела запросов, заголовки, cookies и токены не включаются в результаты QA Check.

### 🔒 Маскирование при экспорте

- По умолчанию в файлах экспорта (HAR, Postman, Markdown, OpenAPI, CSV, cURL), отчётах сессии, баг-репортах, тестах Playwright и промпте для Claude значения токенов, паролей, cookies и API-ключей заменяются на `***`
- Скрываются заголовки (`Authorization`, `Cookie`, `Set-Cookie`, `X-Api-Key` и похожие), секретные параметры URL и поля JSON или формы; схема авторизации сохраняется (`Bearer ***`)
- Персональные данные (e-mail, имена) не маскируются — перед отправкой отчёта проверьте его содержимое
- Не маскируются сохранённые сессии и код cURL/fetch в карточке запроса: они нужны для повторной отправки
- Отключается в настройках: «Скрывать токены, пароли и cookies при экспорте»

### 🔎 Поиск полей в DOM

- Сканируйте DOM страницы, чтобы найти, где используются значения из API-ответов
- Подсвечивайте элементы, использующие определённые поля
- Помогает понять поток данных от API до интерфейса

### 📤 Экспорт

- **HAR** — стандартный формат HTTP Archive
- **Postman** — импорт напрямую в коллекции Postman
- **Claude prompt** — форматированный вывод для помощи AI в отладке
- **Markdown Report** — подробный отчёт об отладке
- **Сессии** — сохраняйте и восстанавливайте историю запросов

### ⚙️ Настройки

- Тёмная тема
- Регулируемый размер шрифта (маленький/средний/большой)
- Язык интерфейса: русский или английский
- Захват: сохранение лога, лимит запросов, типы ресурсов, скорость сети
- Подключение к Jira, экспорт и импорт всех настроек одним файлом
- Избранное для часто используемых запросов

## Быстрая установка (без кода)

1. **Скачайте** архив [`qa-tools.zip`](qa-tools.zip)
2. **Распакуйте** архив в отдельную папку
3. **Откройте Chrome** и перейдите на `chrome://extensions`
4. **Включите** «Режим разработчика» (переключатель в правом верхнем углу)
5. **Нажмите** «Загрузить распакованное расширение» и выберите распакованную папку

Готово! Нажмите на иконку Reqpane на панели инструментов, чтобы начать отладку.

## Установка для разработчиков

1. Клонируйте репозиторий:
   ```bash
   git clone git@github.com:viktormatangovich/Qa-tools.git
   cd Qa-tools/qa-request-inspector
   ```
2. Установите зависимости:
   ```bash
   npm install
   ```
3. Соберите расширение:
   ```bash
   npm run build
   ```
4. Загрузите в Chrome:
   - Перейдите на `chrome://extensions`
   - Включите «Режим разработчика»
   - Нажмите «Загрузить распакованное расширение» и выберите папку `dist`

## Разработка

```bash
cd qa-request-inspector
npm run dev      # Режим слежения — пересборка при изменении файлов
npm run build    # Продакшн-сборка в dist/
npm run zip      # Упаковка dist/ в qa-tools.zip в корне репозитория
npm run release  # Сборка + упаковка
npm run test:qa  # Проверка правил QA, OpenAPI-контракта и граничных сценариев
```

Используется npm (нужен Node.js 22.2 или новее). `npm run zip` не требует утилиты `zip`, работает одинаково на Windows, macOS и Linux, не кладёт в архив скриншоты из `public/` и печатает SHA256 архива.

## Архитектура

```
background.js (service worker + CDP) → App.tsx (боковая панель)
content.js (внедряется по запросу) — поиск/подсветка в DOM, проверки страницы
```

- **`background.js`** — сервис-воркер. Использует `chrome.debugger` API (CDP) для перехвата сетевых запросов через Network domain, перехвата/моков через Fetch domain и захвата консольных ошибок через Runtime domain. Хранит запросы по вкладкам (Map), управляет правилами моков/breakpoint через `chrome.storage.local`. Подключает отладчик при открытии боковой панели, отключает при закрытии.
- **`content.js`** — скрипт для поиска и подсветки полей в DOM и проверок страницы. Не участвует в перехвате сети и не указан в манифесте: панель внедряет его в страницу только при использовании этих функций.
- **`App.tsx`** — React-интерфейс боковой панели. Открывает порт `chrome.runtime.connect` при монтировании для подключения отладчика. Отображает запросы, управляет фильтрацией, экспортом, настройками, моками, точками остановки, сессиями.

## Конфиденциальность

Захваченные данные остаются локально в вашем браузере: расширение ничего не собирает и не отправляет разработчику. Единственное исключение, которое включаете вы сами, — создание задачи в Jira из баг-репорта: текст отчёта и скриншот отправляются на указанный вами сервер Jira после подтверждения. Подробнее — в [PRIVACY.md](qa-request-inspector/PRIVACY.md).


## QA Tools 2.0.0 — инструменты команды

- Профили проектов: окружение, разрешённые домены, настройки QA, OpenAPI, исключения, моки, бизнес-правила и настройки сравнения. Импорт/экспорт JSON.
- Сравнение сессий в обе стороны, повторные вызовы по порядку времени, вложенные JSON-поля, игнорируемые поля, пороги замедления. Числовые ID и UUID в пути объединяются в одну операцию.
- История ограничена тремя сессиями за 24 часа. Просроченные данные удаляются при запуске и по минутному таймеру Chrome; при закрытом браузере — после следующего запуска.
- Ручные шаги с отметкой времени и привязкой запроса, редактируемый текст баг-репорта Jira. Скриншоты и отправка в Jira не добавлены.
- Проверки ответа: наличие поля, равенство, нижняя граница, сумма значений массива. JSON-пути поддерживают индексы и `[*]`.
- Последовательности HTTP-статусов в существующем Mock Engine: повтор последнего ответа, всей последовательности или переход к серверу.
- Пакетные негативные проверки: выбор вариантов и ожидаемого статуса, до 30 последовательных запросов, тайм-аут 10 секунд, остановка. Реальная отправка доступна только на явно указанных доменах локального/тестового профиля. На production используются существующие моки.
- Фильтры инструментов по методу, статусу, заголовкам и JSON ответа; сохранение фильтров в профиль.
- Предпросмотр и экспорт API-тестов и `page.route()` для Playwright. Ожидаемый статус берётся из записи и требует проверки QA.
- OpenAPI JSON/YAML, список неподдерживаемых конструкций, корректный учёт HTTP-операций в покрытии. Проверка сложных схем и внешних ссылок пока не реализована.
- Просмотр WebSocket/SSE с поиском: до 200 сообщений на вкладку, текст сообщения до 64 КиБ. Бинарные WebSocket-кадры остаются в представлении CDP.
- Базовые проверки доступности: положительный tabindex, недоступные с клавиатуры элементы с ролью кнопки/onclick, низкий контраст прямого текста на непрозрачном сплошном фоне. Это частичная проверка, а не полный аудит WCAG.
- Обработка остаётся локальной. Сохранённые сессии хранятся в браузере без маскирования; при экспорте, начиная с 2.1.0, токены, пароли и cookies по умолчанию скрываются (см. «Маскирование при экспорте»).

Проверки: `npm run test:qa`, `npx tsc --noEmit`, `npm run test:ui`. Для браузерной проверки нужен Chromium; путь можно задать через `QA_CHROMIUM_PATH`. Проверка запускается в отдельном профиле и отправляет запросы только на свой локальный стенд.

## QA Tools 2.1.0 — надёжность захвата

- Панель привязана к своему окну: при панелях в нескольких окнах каждая показывает запросы, ошибки консоли и статус отладчика только своей вкладки. Счётчик на иконке считается отдельно для каждой вкладки.
- Захваченные запросы и ошибки переживают перезапуск service worker; панель переподключается сама. Во временном хранилище на вкладку отводится 2 МБ, у более старых запросов сверх этого объёма сохраняется запись без тела.
- Удаление выбранных запросов сохраняется: удалённые записи не возвращаются после переключения вкладки.
- Редирект показывается отдельным запросом со статусом 3xx.
- Моки начинают действовать сразу после сохранения, в том числе созданные из профиля; у замоканного запроса указываются настоящий тип (XHR/fetch) и длительность с учётом задержки.
- Текстовые ответы, которые браузер отдаёт в base64, читаются как UTF-8 — кириллица отображается корректно.
- Добавлено разрешение `unlimitedStorage`: сохранённые сессии с большими телами больше не упираются в квоту 10 МБ. Очистка просроченных сессий не читает их содержимое.
- Архив `qa-tools.zip` уменьшен с 7,7 МБ до 0,2 МБ и корректно распаковывается на macOS и Linux.
- Токены, пароли и cookies по умолчанию скрываются при экспорте; настройка отключается в панели настроек.
- Скрипт расширения больше не загружается на каждой странице и в каждом фрейме: он внедряется только при поиске полей в DOM, подсветке и проверке страницы.
- Панель открывается быстрее: стартовый файл уменьшен с 612 КБ до 302 КБ, редко используемые окна загружаются при первом открытии.
- Файлы экспорта HAR и Postman называются `reqpane-<дата>` вместо `api-debugger-<дата>`.

## QA Tools 2.2.1 — исправления и удобство

- **Мок из захваченного запроса работает.** Раньше мок копировал из реального ответа заголовки `Content-Encoding` и `Content-Length`, и браузер не мог прочитать подменённое тело. Теперь они пересчитываются под новое тело; многострочные заголовки (`Set-Cookie`) передаются корректно.
- **Тела `application/x-www-form-urlencoded`** в «Изменить и отправить» и в окне брейкпоинта можно раскодировать в поля «имя = значение», править и отправлять обратно закодированными. Без правок тело уходит как было.
- **Поиск в ответе по именам полей.** Поиск в дереве JSON находит и ключи, и значения, подсвечивает совпадения и раскрывает их родителей. Фильтр списка запросов ищет по тому же правилу, в том числе в раскодированных формах и в тексте с `\uXXXX`.
- **Узкая боковая панель.** Подписи вкладок, фильтров и кнопок больше не переносятся посреди слова: при нехватке места уменьшаются отступы и шрифт, фильтры переходят во второй ряд, а поля «Метод / Код / Текст / Задержка» в редакторе мока — на следующую строку.
- Запись шагов больше не пишет в консоль «Receiving end does not exist», когда панель закрыта.

## QA Tools 2.2.0 — захват, вмешательство в запросы, отчёты

Захват:

- **Сохранение лога при переходах.** Кнопка со свитком в шапке или настройка «Сохранять лог при переходах между страницами». По умолчанию выключено: список очищается при каждой навигации — и в панели, и в фоновой части (раньше панель продолжала показывать старые запросы до переключения вкладки).
- **Лимит запросов на вкладку** настраивается от 50 до 1000 (по умолчанию 100). Тела хранятся у 200 последних запросов; у более старых остаются заголовки, статус и время.
- **Все типы ресурсов.** С настройкой «Захватывать все ресурсы» в список попадают документы, скрипты, стили, картинки, шрифты и медиа — без тел, со статусом, временем и размером. Над списком появляется фильтр по типу.
- **Настоящие заголовки.** Показываются заголовки, которые браузер действительно отправил и получил, включая `Cookie` и `Set-Cookie`. При экспорте они маскируются так же, как остальные секреты.
- **Время по этапам.** Вкладка «Время» в карточке запроса: ожидание в очереди, DNS, соединение, TLS, отправка, ожидание сервера, загрузка ответа, а также протокол, адрес сервера и объём, переданный по сети. Те же этапы попадают в экспорт HAR.
- **GraphQL.** В списке показывается имя операции (и тип — `mutation`, `subscription`); фильтр по URL ищет и по имени операции.

Вмешательство в запросы:

- **Правка на точке остановки.** Остановленный запрос открывается в окне, где можно изменить URL, метод, заголовки и тело и отправить его изменённым, продолжить как есть или отменить. Несколько остановленных запросов встают в очередь. Автоматическое продолжение — через 5 минут вместо 30 секунд.
- **Остановка на ответе.** У точки остановки появился выбор «Перед отправкой запроса» / «При получении ответа». Во втором случае редактируются статус, заголовки и тело ответа до того, как его получит страница.
- **Действие правила.** У правила в менеджере моков четыре действия: подменить ответ (как раньше), изменить поля настоящего ответа (JSON-путь и новое значение, поддерживаются `[*]` и удаление поля), задержать запрос, заблокировать запрос. Блокировка действует на любые ресурсы — так проверяется работа страницы без аналитики или CDN.
- **Скорость сети.** В настройках: быстрый 3G, медленный 3G, офлайн или свои значения задержки и пропускной способности. Активный режим показывается рядом со счётчиком запросов.

Отчёты и баги:

- **Скриншот в баг-репорте** — видимой части или всей страницы; его можно скачать или отправить вместе с задачей.
- **Создание задачи в Jira** из баг-репорта. Адрес, проект, тип задачи и токен задаются в настройках (Jira Cloud — e-mail и API-токен, Server / Data Center — персональный токен). Перед отправкой показывается подтверждение с адресом сервера. Это единственная функция, которая отправляет данные третьей стороне; подробнее — в [PRIVACY.md](qa-request-inspector/PRIVACY.md).
- **Запись шагов.** «Записать шаги на странице» в инструментах команды: клики, ввод, выбор в списках и переходы становятся шагами воспроизведения с привязкой запросов. Значения полей с паролем не записываются.
- **UI-сценарий Playwright** из записанных шагов: `getByTestId`, `getByRole`, `getByLabel`, `getByPlaceholder` или CSS-селектор — по тому, что есть у элемента. Пароль берётся из переменной окружения. Ожидаемый результат нужно дописать вручную.
- **Импорт HAR** (меню экспорта): файл из DevTools, Charles или самого расширения открывается как список запросов, к нему применимы QA-проверки, контракт и сравнение. Пока показан импортированный файл или сохранённая сессия, новые запросы в список не подмешиваются; кнопка «Вернуться к захвату» возвращает живой список.

Проверки:

- **Контракт OpenAPI.** Проверяются `allOf`, `oneOf`, `anyOf`, `not`, `discriminator`, `pattern`, `format` (date-time, date, email, uuid, uri, ipv4), `const`, `uniqueItems`, `multipleOf`, исключающие границы, `additionalProperties` со схемой, списки типов OpenAPI 3.1, диапазоны статусов (`2XX`), ссылки на параметры, тела и ответы из `components`, параметры уровня пути. Пути сопоставляются с учётом префикса из `servers`; конкретный путь имеет приоритет над шаблонным.
- **Внешние `$ref`.** При загрузке спецификации по URL документы по ссылкам скачиваются и сохраняются вместе со спецификацией; для вставленной спецификации есть кнопка «Загрузить внешние $ref» (относительные ссылки требуют адреса спецификации). Не проверяются `if/then/else`, `contains`, `patternProperties` и подобные — они перечислены в списке неподдерживаемого.
- **Эталонные сессии.** Сессию в истории можно закрепить булавкой: она хранится без срока и не считается в лимите трёх временных.
- **Полный аудит доступности.** «Проверить страницу» дополнительно запускает axe-core (правила WCAG, описания на русском). Библиотека внедряется в страницу только на время проверки и не входит в стартовый файл панели. Отключается в настройках QA-проверок.
- **Бинарные кадры WebSocket** показываются с размером и hex-представлением первых 512 байт.

Удобство:

- **Английский интерфейс** — переключатель «Язык интерфейса» в настройках. Переведены окна, кнопки, настройки и подсказки. Названия и описания найденных QA-проблем, нарушения контракта, отчёт сессии, текст для Jira и комментарии в экспортируемых файлах пока остаются на русском.
- **Перенос настроек одним файлом**: экспорт и импорт темы, языка, захвата, QA-проверок, спецификации, моков, точек остановки, профилей, тегов и параметров Jira (без токена). Захваченные данные в файл не входят.

Проверено автоматически: `npx tsc --noEmit`, `npm run test:qa` (92 теста), `npm run build`. В браузере эта версия на момент сборки не проверялась.

Архив `qa-tools.zip` вырос с 0,2 до 0,46 МБ: в него входит библиотека axe-core для аудита доступности.
